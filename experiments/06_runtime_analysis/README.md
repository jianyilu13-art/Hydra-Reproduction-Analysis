# Experiment 06 – Runtime Verification

## Objective

This experiment verifies the runtime execution of the reproduced Hydra pipeline.

The purpose is to confirm that the compiled Hydra system can correctly receive sensor data, execute the reconstruction and scene graph generation pipeline, and produce visualizable outputs.

Unlike Experiment 04 (Module Analysis), which focuses on static source-code inspection, this experiment focuses on the actual execution behavior of the system.

---

# Experiment Scope

This experiment evaluates the complete runtime process, including:

- launching Hydra with ROS2,
- providing sensor input through rosbag playback,
- checking ROS2 topic communication,
- monitoring Hydra processing,
- generating Dynamic Scene Graph outputs,
- visualizing results through RViz.

---

# Runtime Pipeline

The runtime workflow is:

```
Dataset (ROS2 Bag)
        |
        v
ros2 bag play
        |
        v
ROS2 Sensor Topics
        |
        v
RosInputModule
        |
        v
Hydra Processing Pipeline
        |
        v
Dynamic Scene Graph
        |
        v
Hydra Visualizer
        |
        v
RViz Visualization
```

---

# 1. Dataset Playback

Hydra does not directly read image files or videos during runtime.

Instead, sensor observations are provided through ROS2 messages.

The dataset is stored as a rosbag, which records previously collected sensor data.

During playback:

```
ROS2 Bag
    |
    v
Camera Topics
    |
    v
Hydra Input Module
```

The rosbag acts as a virtual sensor source.

It provides:

- RGB images,
- depth images,
- camera information,
- robot poses,
- TF transformations.

---

# 2. Hydra Execution

After receiving sensor data, Hydra executes its internal modules.

The runtime components include:

## Input Module

Receives ROS2 sensor messages.

Responsibilities:

- subscribe to RGB-D topics,
- synchronize sensor data,
- obtain robot pose information.

---

## Reconstruction Module

Processes geometric observations.

Responsibilities:

- integrate RGB-D observations,
- update TSDF representation,
- generate mesh information.

---

## Frontend

Creates local scene graph information.

Responsibilities:

- generate object nodes,
- create local graph structures,
- associate observations with the scene graph.

---

## Backend

Maintains global consistency.

Responsibilities:

- optimize graph information,
- update the Dynamic Scene Graph,
- handle loop closure constraints.

---

# 3. RViz Visualization

RViz is used only for visualization.

It does not provide:

- sensor input,
- reconstruction,
- semantic inference,
- scene graph generation.

The visualization process is:

```
Dynamic Scene Graph
        |
        v
Hydra Visualizer Node
        |
        v
ROS2 Visualization Messages
        |
        v
RViz
```

RViz displays the results generated by Hydra.

Examples:

| Output | Meaning |
|--------|---------|
| Mesh | Reconstructed geometry |
| Object markers | Semantic objects |
| Places | Spatial regions |
| Rooms | High-level regions |
| Trajectory | Robot movement |

# 5. Runtime Issues and Solutions

During reproduction, several runtime issues were encountered.

Examples include:

## Dataset Compatibility

Some datasets required additional preprocessing or conversion before being used with ROS2 Hydra.

---

## TF Configuration

Incorrect TF message handling affected sensor pose estimation.

Solution:

- use QoS override configuration for `/tf_static`.

---

## Semantic Module Compatibility

Some semantic inference configurations required specific dataset versions or model settings.
