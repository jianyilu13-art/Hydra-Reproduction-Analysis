# Hydra and RViz Visualization

## Objective

This document explains how the Hydra pipeline connects its generated Dynamic Scene Graph (DSG) with RViz visualization.

The goal is to understand the implementation path from Hydra internal data structures to ROS2 visualization messages displayed in RViz.

---

# 1. Overview

RViz is not part of the reconstruction pipeline.

Hydra performs:

```
RGB-D Input
      |
      v
Hydra Pipeline
      |
      v
Dynamic Scene Graph (DSG)
      |
      v
Visualization Interface
      |
      v
RViz
```

RViz only receives and displays the information generated by Hydra.

It does not perform:

- sensor processing
- mesh reconstruction
- object detection
- scene graph optimization

---

# 2. Hydra Visualization Package

The connection between Hydra and RViz is implemented through the `hydra_visualizer` package.

Source location:

```
hydra_ros/
└── hydra_visualizer/
```

Important files:

```
hydra_visualizer/
├── launch/
│   ├── static_visualizer.launch.yaml
│   └── streaming_visualizer.launch.yaml
│
├── config/
│   ├── visualizer_config.yaml
│   ├── visualizer_plugins.yaml
│   └── external_plugins.yaml
```

The visualizer node converts Hydra outputs into ROS2 visualization messages.

---

# 3. Launch Process

The visualization node is started through ROS2 launch files.

Example:

```bash
ros2 launch hydra_visualizer streaming_visualizer.launch.yaml
```

The launch file starts the Hydra visualization node.

The node subscribes to Hydra outputs and publishes visualization information for RViz.

---

# 4. Data Flow Implementation

The complete runtime data flow is:

```
Dataset
  |
  v

  |
  v

  |
  v
RosInputModule

Reconstruction Module

  v
Frontend

  v
Backend

Dynamic Scene Graph
  |
  v
hydra_visualizer node
  |
  v

```

---

# 5. Internal Hydra Output

During processing, Hydra maintains several internal representations:

## Geometry Layer

Generated by:

```
ReconstructionModule
```

Output:

- TSDF representation
- reconstructed mesh

---

## Semantic Layer

Generated by:

```
Frontend
```

Output:

- object nodes
- place nodes
- semantic relationships

---

## Global Graph

Maintained by:

```
BackendModule
```

Output:

- optimized Dynamic Scene Graph
- globally consistent scene representation

---

# 6. Visualization Conversion

Hydra internal data structures cannot be directly displayed by RViz.

Therefore, the visualizer converts them into ROS2 messages.

Example conversion:

```
DynamicSceneGraph
        |
        v
Visualization Messages
        |
        v
RViz Marker / Mesh Messages
```

The visualization layer publishes:

| Hydra Data | RViz Representation |
|-|-|
| Mesh | Mesh visualization |
| Object nodes | Marker objects |
| Place nodes | Graph markers |
| Room nodes | High-level regions |
| Robot trajectory | Path visualization |

---

# 7. RViz Display

RViz subscribes to the visualization topics published by Hydra.

The user can enable displays such as:

- Mesh
- Marker
- PointCloud
- TF
- Path

The visualization allows inspection of:

- reconstruction quality
- semantic object detection
- hierarchical scene graph structure

---

# 8. Verification Method

The connection can be verified using ROS2 commands.

Check running nodes:

```bash
ros2 node list
```

Expected:

```
/hydra
/hydra_visualizer
/rviz
```

Check published topics:

```bash
ros2 topic list
```

Check visualization messages:

```bash
ros2 topic echo <topic_name>
```

RViz should display the corresponding Hydra output.

---

# 9. Expected Outcome

This experiment should demonstrate:

1. Hydra successfully generates a Dynamic Scene Graph.
2. The `hydra_visualizer` package converts Hydra outputs into ROS2 visualization messages.
3. RViz receives these messages and provides a visual representation of the reconstructed environment.

Therefore:

```
Hydra = reconstruction and reasoning

Hydra Visualizer = ROS2 visualization bridge

RViz = visualization interface
```
