# Hydra Scene Graph Layer Analysis

## Objective

This experiment analyzes the internal structure of Hydra's Dynamic Scene Graph (DSG).

The goal is to understand how Hydra transforms geometric reconstruction into a hierarchical representation of the environment.

This analysis focuses on:

- the different layers of the Dynamic Scene Graph,
- the technical representation used by each layer,
- the algorithms involved in generating different layers,
- the relationship between geometry and semantic information.

Unlike Experiment 04 (Pipeline Verification), which focuses on software modules and execution flow, this experiment focuses on the final scene graph representation.

---

# 1. Dynamic Scene Graph Overview

Hydra represents the environment using a hierarchical Dynamic Scene Graph (DSG).

Traditional mapping systems mainly represent environments using geometric information:

```
Environment
    |
    v
Dense Geometric Map
```

Hydra extends this representation by introducing multiple abstraction levels:

```
Dynamic Scene Graph

    Room Layer
        |
        v
    Place Layer
        |
        v
    Object Layer
        |
        v
    Mesh Layer
```

Different layers represent the environment at different levels of abstraction.

Lower layers provide detailed geometric information, while higher layers provide structured spatial understanding.

---

# 2. Mesh Layer

## Purpose

The mesh layer represents the reconstructed geometric structure of the environment.

It is the foundation of the Dynamic Scene Graph.

The mesh layer answers:

> "Where does physical geometry exist?"

---

## Technical Representation

Hydra uses volumetric reconstruction based on TSDF (Truncated Signed Distance Function).

The reconstruction process can be summarized as:

```
RGB-D Observations
        |
        v
       TSDF
        |
        v
       Mesh
```

---

## TSDF Representation

TSDF represents the environment as a voxel volume.

Each voxel stores information about the distance to the nearest observed surface.

A simplified voxel representation:

```
Voxel

+----------------+
| Distance Value |
| Weight         |
| Occupancy      |
+----------------+
```

TSDF provides:

- surface estimation,
- sensor fusion,
- noise reduction.

Multiple RGB-D observations can be integrated into a consistent geometric representation.

---

## Mesh Generation

The TSDF volume is converted into a mesh representation.

The mesh contains:

- vertices,
- triangles,
- surface geometry.

Example:

```
TSDF Volume
      |
      v
Surface Extraction
      |
      v
Triangle Mesh
```

The mesh represents physical structure but does not contain semantic meaning by itself.

---

## Related Source Code

Reconstruction module:

```

```

Class:


Responsibilities:

- maintain local reconstruction,
- update geometric information,
- provide mesh information for later processing.

# 3. Object Layer

## Purpose

The object layer adds semantic entities to the geometric reconstruction.

Instead of only representing surfaces, Hydra identifies meaningful objects.

The object layer answers:

> "What objects exist in the environment?"

---

## Technical Process

Objects are generated by combining geometry and semantic information.

The general process:

```
Mesh
 |
 v
Mesh Segmentation
 |
 v
Object Nodes
```

---

## Object Representation

An object node contains information such as:

```
Object Node

+----------------+
| Category       |
| Position       |
| Geometry       |
| Semantic Label |
+----------------+
```

Examples:

```
Chair

Table

Monitor

Door
```

Each object node is associated with a corresponding region of the reconstructed mesh.

---

## Semantic Inference

Semantic information can be obtained from semantic inference modules.

The process is:

```
Image
 |
 v
Semantic Prediction
 |
 v
Object Label
 |
 v
Scene Graph Object
```

Semantic inference provides object categories that can be attached to geometric regions.

# 4. Place Layer

## Purpose

The place layer represents spatial regions in the environment.

Instead of describing individual objects, places describe groups of connected spatial areas.

The place layer answers:

> "Which spatial region does this area belong to?"

---

# ESDF Representation

Hydra uses ESDF (Euclidean Signed Distance Field) for spatial reasoning.

Compared with TSDF:

| Representation | Purpose |
|----------------|---------|
| TSDF | Surface reconstruction |
| ESDF | Spatial distance and free-space reasoning |

ESDF provides:

- distance to obstacles,
- free-space structure,
- spatial connectivity information.

---

# GVD Place Extraction

Hydra uses GVD (Generalized Voronoi Diagram) to generate place-level structures.

The process:

```
ESDF
 |
 v
GVD
 |
 v
Place Nodes
```

The GVD represents the center structure of free space.

It helps identify meaningful spatial regions for navigation and scene understanding.

Example:

```
Environment

Place 1
 |
 +--- Object A
 +--- Object B

Place 2
 |
 +--- Object C
 +--- Object D
```

---

## Related Source Code

GVD configuration:

```
~/hydra_ws/src/hydra_ros/hydra_ros/config/sinks/gvd_places_sinks.yaml
```

The place layer is generated mainly from geometric free-space analysis rather than only semantic labels.

# 5. Room Layer

## Purpose

The room layer represents high-level spatial regions.

It groups multiple places into larger areas and provides a more abstract organization of the environment.

The room layer answers:

> "Which larger spatial region does this area belong to?"

---

## Representation

A room node contains:

- connected place nodes,
- spatial relationships,
- region-level information.

Example:

```
Room Layer

Room 1
 |
 +--- Place A
 |
 +--- Place B


Room 2
 |
 +--- Place C
 |
 +--- Place D
```

---

## Semantic Meaning

Hydra does not automatically understand human room names such as:

- kitchen,
- bedroom,
- office,
- living room.

Instead, rooms are usually represented as anonymous regions:

```
Room 1

Room 2

Room 3
```

The room layer describes spatial organization rather than directly performing room classification.

Additional semantic methods are required if human-readable labels are needed.

Example:

```
Geometric Representation:

Room 1
Room 2
Room 3


Semantic Interpretation:

Room 1 -> Office
Room 2 -> Kitchen
Room 3 -> Bedroom
```

---

## Importance

The room layer allows robots to reason about larger-scale structures.

Instead of only understanding:

```
Object:

Chair

Position:

(x,y,z)
```

the robot can understand:

```
Chair
 |
 v
Room 1
 |
 v
Building Structure
```

This hierarchical organization supports:

- navigation,
- planning,
- scene understanding.

# 6. Relationship Between Layers

The complete hierarchy is:

```
Room Layer
    |
    v
Place Layer
    |
    v
Object Layer
    |
    v
Mesh Layer
    |
    v
TSDF / ESDF Representation
```

Each layer provides different information:

| Layer | Main Question | Technical Method |
|-------|---------------|----------------|
| Mesh | Where is geometry? | TSDF reconstruction |
| Objects | What exists? | Semantic inference + segmentation |
| Places | Where are spatial regions? | ESDF + GVD |
| Rooms | How are regions organized? | DSG hierarchy |

# Expected Outcome

This experiment explains how Hydra extends traditional mapping into hierarchical scene understanding.

The final Dynamic Scene Graph combines:

- TSDF-based geometric reconstruction,
- ESDF-based spatial reasoning,
- GVD-based place extraction,
- semantic object representation,
- hierarchical spatial organization.

Hydra therefore provides robots with a structured representation of environments that supports higher-level perception, navigation, and reasoning.
